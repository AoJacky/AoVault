# 知识库笔记整理

将粗略笔记、微信摘录、课堂记录等素材，整理为 `AoVault/知识库/` 下的统一格式。

## 触发条件

当用户要求"整理笔记"、"按知识库结构整理"、"补充摘要/要点"时使用本 skill。

## 标准结构模板

每篇知识库笔记必须包含以下区块，按顺序排列：

```markdown
---
title: "笔记标题"
date: YYYY-MM-DD
tags: [知识库, 一级分类, 具体主题标签...]
source: "来源（微信公众号名 / 书籍名 / 论文名 / 笔记整理）"
---

# 笔记标题

> 一句话摘要：用一句话概括这篇笔记最核心的结论或知识点。

## 摘要

用一段完整的话（2-5 句）阐述这篇笔记的核心内容。覆盖：是什么、为什么重要、关键结论。不堆砌细节，只给全貌。

## 原文要点

按逻辑分成若干小节（### 1. xxx / ### 2. xxx），把原始素材中的关键信息结构化呈现。

要求：
- 用列表、表格、公式等 Markdown 语法组织信息，不要照搬原文的松散段落
- 涉及公式时用 `$...$`（行内）或 `$$...$$`（独立行）
- 有对比信息时优先用表格
- 保留原文中的图片嵌入（`![[image.png]]`），放在对应小节内
- 如果原文有代码/公式推导，保留并用代码块或公式块格式化

## 个人想法

留空或写 1-2 句启发性的思考。此区块始终保留，即使暂时为空也保留标题。

## 原文链接

填写来源链接。如果是微信整理，写"微信整理"；如果是笔记整理，写"笔记整理"。
```

## Frontmatter 规则

### 字段说明

| 字段 | 必填 | 格式 | 说明 |
|------|------|------|------|
| title | 是 | `"字符串"` | 笔记标题，与 `# 标题` 一致 |
| date | 是 | `YYYY-MM-DD` | 创建日期，用当天日期 |
| tags | 是 | `[数组]` | 第一个标签固定为 `知识库`，第二个为一级分类（如 `电机控制`），后续为具体主题 |
| source | 是 | `"字符串"` | 信息来源，微信类写公众号名，无来源写"笔记整理" |

### Tags 命名规范

- 一级标签：与笔记所在文件夹名一致（如 `电机控制`、`嵌入式`、`AI`）
- 二级标签：笔记的核心主题词（如 `FOC`、`电流采样`、`PID`）
- 避免过细的标签，控制在 3-6 个

## 整理流程

1. **读取原始笔记**：理解现有内容，区分哪些是有效知识点、哪些是草稿/碎片
2. **读取同目录下 2-3 篇已有笔记**：确认该分类的常见标签和写法风格
3. **补充 frontmatter**：按规则填写 title / date / tags / source
4. **写一句话摘要**（`>` blockquote）：提炼最核心的一句话结论
5. **写摘要段落**：2-5 句话覆盖全貌，让读者不看正文也能了解大意
6. **重组原文要点**：
   - 将松散内容按逻辑分成小节（`### 1. xxx`）
   - 列表、表格、公式、图片归入对应小节
   - 删除重复和无意义的碎片
   - 必要时补充少量背景说明帮助理解（但不添加原文没有的结论）
7. **保留个人想法区**：即使为空也保留标题
8. **填写原文链接**

## 常见一级分类

| 分类 | 目录 | 典型标签 |
|------|------|----------|
| 电机控制 | `AoVault/知识库/电机控制/` | FOC, PMSM, 电流采样, PWM, 解耦, 无感控制 |
| 嵌入式 | `AoVault/知识库/嵌入式/` | STM32, HAL, 中断, DMA, RTOS |
| AI | `AoVault/知识库/AI/` | LLM, Prompt, Agent |
| 工具 | `AoVault/知识库/工具/` | Obsidian, Git |
| 其他 | `AoVault/知识库/其他/` | 通用知识 |

如果用户在新分类下工作，先确认分类名再创建标签。

## 注意事项

- 不要改变文件位置，只在原地编辑
- 保留所有原有图片嵌入链接
- 保留所有原有外部链接
- 不要删除用户已有的个人想法内容
- 公式统一用 `$...$` 格式，不用 `\[...\]`
- 表格用 GitHub Flavored Markdown 格式
